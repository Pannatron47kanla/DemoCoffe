# UC-04 หน้าจอตู้และหน้าสถานะออเดอร์บนมือถือ (Kiosk screen)

- **Context:** UI ตู้ (Next.js ใหม่ ไม่ใช่ module ใน `src/modules/`) เรียก API ของ menu, ordering และ voice; เพิ่ม endpoint ใน menu (อ่านเมนู) และ ordering (อ่านออเดอร์); แก้การตั้งค่าโทเคนใน voice (คำบรรยาย)
- **เฟส:** 1 MVP — ตู้เดี่ยว ใช้กับพนักงานหรือผู้ทดสอบที่ยินยอมเท่านั้น (เงื่อนไขเดียวกับ UC-02)
- **สถานะ:** ผู้ใช้อนุมัติขอบเขตและหน้าจอแล้ว (2026-10-20) รอรีวิว AC
- **อ้างอิง:** ข้อเสนอสถาปัตยกรรม หัวข้อ "บัตรคิว" (ตู้แสดงหมายเลขคิวพร้อม QR ที่เปิดหน้าสถานะบนมือถือ ลิงก์เดาไม่ได้ ไม่ต้องล็อกอิน), UC-01 (ตะกร้าและยืนยัน), UC-02 (ความยินยอมและโทเคน), UC-03 (function call), mockup ใน `.superpowers/brainstorm/` (`flow-v2.html`, `voice-answer.html` ตัวเลือก B)

## ผู้ใช้งาน
- ลูกค้าหน้าตู้ (สั่งด้วยการแตะ และสั่งด้วยเสียงถ้ายินยอม)
- ลูกค้าที่สแกน QR บนมือถือของตัวเอง (ดูหมายเลขคิวและรายการ)

## เงื่อนไขก่อนเริ่ม
- `api` เสิร์ฟ UI ตู้ (ไฟล์ static ที่ build จาก Next.js แบบ `output: 'export'`) ที่ origin เดียวกับ API ไม่มี node ใหม่ใน `docker compose`
- เมนูอยู่ใน `data/menu.json` ข้อความยินยอมอยู่ใน `data/voice-consent.json`
- การตั้งค่าใหม่ของ `api`: `PUBLIC_BASE_URL` คือ URL ที่มือถือลูกค้าเปิดได้ ใช้สร้างลิงก์ใน QR (ค่าเริ่มต้น `http://localhost:3000`) ผู้ใช้เป็นผู้นำ `api` ขึ้น host เอง
- หน้าจอเป็นภาษาไทยอย่างเดียว วางแนวตั้ง

## หน้าจอและขั้นตอนหลัก
1. **หน้าต้อนรับ:** ลูกค้าแตะ "เริ่มสั่ง" → ตู้สร้างตะกร้า (`POST /carts`) และโหลดเมนู (`GET /menu`) แล้วเปิดหน้าสั่ง
2. **หน้าสั่ง** (เมนู + ตะกร้า + ปุ่มเสียงในหน้าเดียว ไม่มีปุ่ม "สั่งด้วยการแตะ" แยก เพราะการแตะเมนูคือวิธีหลัก)
   - แตะเมนู → หน้าต่างตัวเลือก (กลุ่มที่ต้องเลือกมีเครื่องหมาย ราคาเพิ่มของแต่ละตัวเลือก จำนวน 1–10) → "ใส่ตะกร้า" (`POST /carts/{cartId}/lines`)
   - เมนูที่หมดแสดงจางและแตะไม่ได้
   - ในตะกร้าแก้จำนวนหรือลบรายการได้ แสดงยอดรวมจาก response ของ API เท่านั้น ตู้ไม่คิดราคาเอง
   - แตะ 🎤 "สั่งด้วยเสียง" ครั้งแรกในตะกร้านี้ → แผ่นข้อความยินยอม (`GET /voice/consent-text`) มีปุ่ม "ยินยอม" และ "ไม่ใช่ตอนนี้" ขนาดเท่ากัน
   - "ยินยอม" → `POST /voice/sessions` → ตู้เปิด Gemini Live ด้วยโทเคนที่ได้ ส่งเสียงไมโครโฟน เล่นเสียงตอบ
   - ระหว่างเปิดเสียง: ปุ่มเปลี่ยนเป็น "⏹ หยุดเสียง" และมีกล่องคำบรรยายแสดงสิ่งที่ลูกค้าพูด (👤) กับที่ Gemini ตอบ (🤖)
   - function call จาก Gemini → ตู้ส่งต่อที่ `POST /voice/sessions/{sessionId}/function-calls` ตรงๆ ไม่ตีความเอง ส่ง body กลับให้ Gemini และแสดงตะกร้าจาก response
   - `request_checkout` ได้ `action: SHOW_CHECKOUT` → ตู้เปิดหน้ายืนยัน
3. **หน้ายืนยัน:** สรุปรายการและยอด "ยืนยันสั่ง" (`POST /carts/{cartId}/checkout` พร้อม `Idempotency-Key`) หรือ "กลับไปแก้"
4. **หน้าหมายเลขคิว:** หมายเลขคิวตัวใหญ่ และ QR ของ `statusPageUrl` จาก response ของ checkout → กลับหน้าต้อนรับเองหลัง 30 วินาที หรือเมื่อแตะ "เสร็จสิ้น"
5. **หน้าสถานะบนมือถือ** (`/q/?order=<orderId>`): แสดงหมายเลขคิว สถานะ รายการ (ชื่อ ตัวเลือก จำนวน ราคา) และยอดรวม จาก `GET /orders/{orderId}`

## กฎทางธุรกิจ
| # | กฎ |
|---|---|
| R1 | ตู้ไม่คิดราคาและไม่ตรวจกฎตะกร้าเอง แสดงตามที่ API ตอบเท่านั้น error จาก API แสดงเป็นข้อความไทยตาม `code` |
| R2 | ต้องยินยอมก่อนจึงเปิดเสียงได้ (UC-02 R1) ปุ่ม "ยินยอม" และ "ไม่ใช่ตอนนี้" ขนาดเท่ากัน "ไม่ใช่ตอนนี้" ปิดแผ่นยินยอม ไม่เรียก API ถ้าตะกร้ามีเซสชันเสียงแล้ว แตะ 🎤 อีกครั้งไม่แสดงแผ่นยินยอมซ้ำ (UC-02 R4) |
| R3 | ตู้ส่ง function call ให้ `api` ตามที่ได้รับ ส่ง body ของ 200/400/404/409 กลับให้ Gemini ถ้าได้ 503/500 ปิดเสียง แสดงข้อความ "ใช้เสียงไม่ได้ตอนนี้ สั่งด้วยการแตะได้เลย" ตะกร้าเดิมใช้ต่อได้ (UC-03 R7) |
| R4 | เปิดเสียงไม่สำเร็จ (`POST /voice/sessions` ได้ 503 หรือเชื่อมต่อ Gemini ไม่ได้) หรือการเชื่อมต่อหลุด ให้ทำเหมือน R3 ลูกค้าแตะ 🎤 ใหม่ได้ (ได้โทเคนใหม่ตาม UC-02 R4 โดยไม่ถามยินยอมซ้ำ) |
| R5 | "หยุดเสียง" ปิดการเชื่อมต่อ Gemini และไมโครโฟนทันที ตะกร้าไม่เปลี่ยน |
| R6 | คำบรรยายแสดงบนจอเท่านั้น ไม่ส่งไป `api` และไม่บันทึก (UC-03 R6) ล้างเมื่อจบออเดอร์หรือกลับหน้าต้อนรับ โทเคนที่ `api` ออกต้องล็อกการเปิดคำบรรยายทั้งขาเข้าและขาออก |
| R7 | ยืนยันออเดอร์ด้วยการแตะ "ยืนยันสั่ง" บนจอเท่านั้น (UC-03 R3) ตู้สร้าง `Idempotency-Key` หนึ่งค่าต่อหน้ายืนยันหนึ่งครั้ง กดซ้ำหรือส่งซ้ำใช้ key เดิม |
| R8 | ยืนยันไม่ผ่านเพราะเมนูหมดหรือราคาเปลี่ยน (`MENU_ITEM_UNAVAILABLE`, `PRICE_CHANGED`) กลับหน้าสั่งพร้อมข้อความ และไฮไลต์รายการที่มีปัญหา ตะกร้าหมดอายุ (`CART_EXPIRED`) แสดงข้อความแล้วกลับหน้าต้อนรับ |
| R9 | ลิงก์ใน QR คือ `PUBLIC_BASE_URL` + `/q/?order=<orderId>` `orderId` เป็น UUID แบบสุ่มจึงเดาไม่ได้ ไม่ต้องล็อกอิน |
| R10 | หน้าสถานะและ `GET /orders/{orderId}` แสดงเฉพาะ หมายเลขคิว สถานะ เวลาสั่ง รายการ และยอดรวม ไม่แสดง `cartId` หรือ `Idempotency-Key` สถานะเฟส 1 มีค่าเดียวคือ `PLACED` แสดงว่า "รับออเดอร์แล้ว" |
| R11 | ไม่มีการแตะในหน้าสั่งหรือหน้ายืนยัน 2 นาที ขณะไม่ได้เปิดเสียง → ถาม "ยังสั่งอยู่ไหม" ถ้าไม่แตะใน 15 วินาที กลับหน้าต้อนรับ (ตะกร้าเดิมปล่อยให้หมดอายุเองตาม UC-01) |
| R12 | หน้าหมายเลขคิวกลับหน้าต้อนรับเองหลัง 30 วินาที |

## นอกขอบเขต
- แจ้งเตือนบนมือถือเมื่อเครื่องดื่มพร้อม และการเปลี่ยนสถานะโดยพนักงาน (ต้องมีเว็บร้าน เฟสถัดไป `orders.status` มีแค่ `PLACED`)
- การนำ `api` ขึ้น host หรือ tunnel สำหรับ QR (ผู้ใช้ทำเอง) — **ข้อควรระวัง:** ถ้าเปิด `api` ทั้งหมดสู่สาธารณะ ใครก็สร้างตะกร้า ออเดอร์ และเซสชันเสียง (ใช้โควตา Gemini) ได้ เพราะเฟส 1 ไม่มีคีย์ตู้ ควรเปิดเฉพาะ `/q/` `/_next/` และ `GET /orders/{orderId}`
- ชำระเงิน ใบหน้า สมาชิก ทักทายด้วยชื่อ (UC ถัดไป)
- การต่อเซสชันเสียงแบบไร้รอยต่อ (session resumption อัตโนมัติเมื่อการเชื่อมต่อครบ ~10 นาที) เฟสนี้ใช้ R4: แจ้งว่าหลุดแล้วให้แตะ 🎤 ใหม่
- ตั้งค่าเสียงของ Gemini (`voiceConfig`) ใช้เสียงเริ่มต้น
- ล็อกเครื่องด้วย Edge kiosk mode / Assigned Access
