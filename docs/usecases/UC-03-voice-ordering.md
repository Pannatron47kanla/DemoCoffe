# UC-03 สั่งเครื่องดื่มด้วยเสียง (Voice ordering)

- **Context:** voice (เรียกตะกร้าของ ordering ผ่าน port, อ่านเมนูจาก menu ผ่าน port)
- **เฟส:** 1 MVP — ตู้เดี่ยว ใช้กับพนักงานหรือผู้ทดสอบที่ยินยอมเท่านั้น (เงื่อนไขเดียวกับ UC-02)
- **สถานะ:** ยืนยัน AC แล้ว (2026-10-20) พร้อมทำขั้นที่ 2
- **อ้างอิง:** ข้อเสนอสถาปัตยกรรม หัวข้อ "สั่งและตอบกลับด้วยเสียง" (Gemini ไม่แก้ตะกร้าเอง เรียกฟังก์ชันของเซิร์ฟเวอร์ เซิร์ฟเวอร์ตรวจกับเมนูจริงแล้วส่งผลกลับ), UC-01 (กฎตะกร้า), UC-02 (ความยินยอมและโทเคน)

## ผู้ใช้งาน
- ลูกค้าหน้าตู้ที่ยินยอมเรื่องเสียงแล้ว (UC-02) และมีเซสชันเสียงเปิดอยู่

## เงื่อนไขก่อนเริ่ม
- ตะกร้ามีเซสชันเสียงจาก UC-02 (ตู้รู้ `sessionId` จาก response ของ `POST /voice/sessions`)
- ตะกร้ายังเปิดและไม่หมดอายุ
- เมนูอยู่ใน `data/menu.json` (อ่านใหม่ทุกครั้ง)

## ขั้นตอนหลัก
1. ตอน UC-02 ออกโทเคน ระบบใส่ไว้ในโทเคนด้วย (ล็อกไว้ ตู้แก้ไม่ได้): คำสั่งระบบ (system instruction) ที่มีเมนูปัจจุบัน, รายการฟังก์ชันที่ Gemini เรียกได้, และภาษาพูด `th-TH`
2. ลูกค้าพูด เช่น "ลาเต้แก้วใหญ่ นมโอ๊ต สองแก้ว"
3. Gemini จับคู่คำพูดกับเมนู แล้วส่ง function call เช่น `add_to_cart { menuItemId: "latte", optionChoiceIds: ["size-l", "milk-oat"], quantity: 2 }` มาที่ตู้
4. ตู้ส่งต่อ function call ให้ `api` ทันที (`POST /voice/sessions/{sessionId}/function-calls`) ตู้ไม่ตีความเอง
5. `api` หาตะกร้าจากเซสชันเสียง (ไม่รับ `cartId` จาก Gemini) แล้วเรียก use case ของ ordering ชุดเดียวกับการแตะจอ กฎ UC-01 ใช้ครบทุกข้อ
6. `api` ตอบตะกร้าล่าสุด หรือ error ตาม code ของ UC-01 ตู้ส่ง body นั้นกลับให้ Gemini เป็น function response และแสดงตะกร้าจาก response นั้นบนจอ
7. Gemini พูดตอบสั้นๆ ตามผลจริง เช่น "เพิ่มลาเต้ L นมโอ๊ต 2 แก้วแล้วค่ะ ยอดรวม 160 บาท"
8. ลูกค้าบอกว่าพอแล้ว หรือขอจ่ายเงิน → Gemini เรียก `request_checkout` → `api` ตอบให้ตู้เปิดหน้าสรุปออเดอร์ ลูกค้ายืนยันด้วยการแตะจอเท่านั้น (UC-01 checkout)

## ฟังก์ชันที่ Gemini เรียกได้
| ชื่อ | args | ผล |
|---|---|---|
| `add_to_cart` | `menuItemId` (ต้องมี), `optionChoiceIds` (ไม่บังคับ ค่าเริ่มต้น `[]`), `quantity` (ต้องมี) | เหมือน UC-01 เพิ่มรายการ (รวมกับรายการเดิมถ้าชุดเดียวกัน) |
| `change_quantity` | `lineId`, `quantity` | เหมือน UC-01 แก้จำนวน |
| `remove_from_cart` | `lineId` | เหมือน UC-01 ลบรายการ |
| `view_cart` | — | ตะกร้าล่าสุด |
| `request_checkout` | — | ขอให้ตู้เปิดหน้าสรุปออเดอร์ ไม่ยืนยันออเดอร์ |

## กฎทางธุรกิจ
| # | กฎ |
|---|---|
| R1 | Gemini ไม่แก้ตะกร้าเอง ทุกการเปลี่ยนแปลงผ่านฟังก์ชันในตารางข้างบนเท่านั้น และผ่านกฎ UC-01 ทุกข้อ (เมนูมีอยู่ หมดแล้ว ตัวเลือกบังคับ 1–10 แก้วต่อรายการ ไม่เกิน 20 แก้ว หมดอายุ 15 นาที) |
| R2 | ตะกร้าที่ฟังก์ชันใช้มาจากเซสชันเสียงเท่านั้น Gemini ระบุตะกร้าเองไม่ได้ และแก้รายการของตะกร้าอื่นไม่ได้ |
| R3 | ยืนยันออเดอร์ด้วยการแตะจอเท่านั้น `request_checkout` ไม่สร้างออเดอร์และไม่เปลี่ยนสถานะตะกร้า |
| R4 | คำสั่งระบบมีเมนูปัจจุบันตอนออกโทเคน: id ชื่อ ราคา (บาท) กลุ่มตัวเลือก (ต้องเลือกหรือไม่) ตัวเลือกและราคาเพิ่ม และเมนูที่หมดให้ระบุว่าหมด ถ้าเมนูเปลี่ยนระหว่างเซสชัน เซิร์ฟเวอร์ยังตรวจกับเมนูจริงทุกครั้ง (R1) |
| R5 | คำสั่งระบบสั่งให้ Gemini: พูดไทยสั้นๆ, ถามตัวเลือกที่ต้องเลือกก่อนเรียก `add_to_cart`, ไม่เดาเมนูที่ไม่มี (ให้บอกว่าไม่มีแล้วเสนอเมนูใกล้เคียง), พูดราคาและรายการตามผลของฟังก์ชันเท่านั้น, เมื่อลูกค้าจะจ่ายเงินให้เรียก `request_checkout` แล้วบอกให้แตะยืนยันบนจอ |
| R6 | ไม่บันทึกข้อความที่พูด เสียง หรือประวัติการเรียกฟังก์ชัน (ต่อจาก UC-02 R3) การเรียกฟังก์ชันนับเป็นการแก้ไขตะกร้าเหมือนการแตะจอ (ต่ออายุตะกร้าตาม UC-01) |
| R7 | ผิดกฎหรือไม่พบข้อมูล ตอบ status และ code เดียวกับ UC-01 ตู้ส่ง body ให้ Gemini ทุกกรณีที่เป็น 400/404/409 เพื่อให้ Gemini อธิบายลูกค้า ส่วน 503/500 ตู้ปิดเสียงและกลับไปสั่งด้วยการแตะ |
| R8 | ถ้าปิดใช้เสียงอยู่ (UC-02 R8) เรียกฟังก์ชันไม่ได้ ตอบ 503 `VOICE_UNAVAILABLE` |

## Acceptance criteria
| AC | Given | When | Then |
|---|---|---|---|
| AC1 | เมนูมีลาเต้ อเมริกาโน่ เอสเพรสโซ่ และมัทฉะลาเต้ที่หมด | ระบบขอโทเคน (UC-02) | คำขอล็อกคำสั่งระบบที่มีทุกเมนูพร้อม id ชื่อ ราคาบาท กลุ่มตัวเลือก (ต้องเลือกหรือไม่) และตัวเลือก มัทฉะลาเต้ระบุว่าหมด ล็อกฟังก์ชันทั้ง 5 ตัวพร้อม schema ของ args และภาษา `th-TH` |
| AC2 | AC1 | ดูคำสั่งระบบ | มีข้อปฏิบัติตาม R5 ครบ และไม่มีข้อมูลบุคคล cartId หรือ kioskId (UC-02 R7) |
| AC3 | ตะกร้าว่าง มีเซสชันเสียง | `add_to_cart` ลาเต้ `size-l` `milk-oat` 2 แก้ว | 200 ตะกร้ามีลาเต้ L นมโอ๊ต 2 แก้ว ยอด 160.00 บาท (เหมือน UC-01 AC2) |
| AC4 | ตะกร้ามีลาเต้ L นมโอ๊ต 2 แก้ว | `change_quantity` เป็น 4 | 200 รายการนั้นเป็น 4 แก้ว |
| AC5 | ตะกร้ามีลาเต้ 1 รายการ | `remove_from_cart` | 200 ตะกร้าว่าง |
| AC6 | ตะกร้ามีลาเต้ 2 แก้ว | `view_cart` | 200 ตะกร้าล่าสุด ไม่เปลี่ยนอะไร |
| AC7 | ตะกร้ามีลาเต้ 2 แก้ว | `request_checkout` | 200 `action: SHOW_CHECKOUT` พร้อมตะกร้า ตะกร้ายัง `OPEN` ไม่มีออเดอร์ใหม่ |
| AC8 | ตะกร้าว่าง | `request_checkout` | 409 `CART_EMPTY` |
| AC9 | — | `add_to_cart` อเมริกาโน่โดยไม่เลือกขนาด | 409 `OPTION_REQUIRED` พร้อม `groupId: size` |
| AC10 | — | `add_to_cart` เมนู `bubble-tea` ที่ไม่มี | 404 `MENU_ITEM_NOT_FOUND` |
| AC11 | มัทฉะลาเต้หมด | `add_to_cart` มัทฉะลาเต้ | 409 `MENU_ITEM_UNAVAILABLE` |
| AC12 | ตะกร้ามี 18 แก้ว | `add_to_cart` อีก 3 แก้ว | 409 `CART_LIMIT_REACHED` (และ 11 แก้วต่อรายการได้ `QUANTITY_OUT_OF_RANGE`) |
| AC13 | ตะกร้า A และ B มีเซสชันเสียงคนละอัน | เซสชันของ A เรียก `change_quantity` หรือ `remove_from_cart` ด้วย `lineId` ของ B | 404 `CART_LINE_NOT_FOUND` ตะกร้า B ไม่เปลี่ยน |
| AC14 | — | ใช้ `sessionId` ที่ไม่มี | 404 `VOICE_SESSION_NOT_FOUND` |
| AC15 | ตะกร้าของเซสชันไม่ได้แก้ไขครบ 15 นาที หรือยืนยันออเดอร์แล้ว | เรียกฟังก์ชันใดก็ได้ | 409 `CART_EXPIRED` หรือ `CART_ALREADY_CHECKED_OUT` |
| AC16 | — | ชื่อฟังก์ชันไม่อยู่ในตาราง หรือ args ผิดรูปแบบ (เช่นไม่มี `menuItemId`, `quantity` ไม่ใช่จำนวนเต็ม) | 400 `VALIDATION_ERROR` พร้อม `fields` |
| AC17 | ปิดใช้เสียงไว้ | เรียกฟังก์ชัน | 503 `VOICE_UNAVAILABLE` ตะกร้าไม่เปลี่ยน |
| AC18 | ตะกร้าแก้ไขล่าสุดเมื่อ 10 นาทีก่อน | `add_to_cart` สำเร็จ | ตะกร้าต่ออายุ หมดอายุ 15 นาทีนับจากตอนนี้ (เหมือนแตะจอ) |

## นอกขอบเขต
- โค้ดฝั่งตู้: เปิด WebSocket กับ Gemini, เสียงเข้าออก, ส่งต่อ function call, แสดงตะกร้า ปุ่มหยุดเสียง (UC หน้าจอตู้)
- คุณภาพการเข้าใจภาษาพูดของ Gemini (ทดสอบด้วยสคริปต์เดโมด้านล่าง ไม่ใช่ AC อัตโนมัติ)
- ยืนยันออเดอร์ด้วยเสียง (ห้ามตาม R3)
- สั่งซ้ำ ทักทาย สมาชิก (เฟสถัดไป)

## สคริปต์เดโม (ตรวจด้วยคน ไม่ใช่เทสต์อัตโนมัติ)
1. "ลาเต้แก้วใหญ่ นมโอ๊ต สองแก้ว" → เพิ่มถูก พูดยอด 160 บาท
2. "อเมริกาโน่หนึ่งแก้ว" → ถามขนาดก่อน ไม่เรียกฟังก์ชันจนกว่าจะได้คำตอบ
3. "มัทฉะลาเต้" → บอกว่าหมด เสนอเมนูอื่น
4. "ชานมไข่มุก" → บอกว่าไม่มี ไม่เดา
5. "เปลี่ยนลาเต้เป็นแก้วเดียว" / "เอาออก" → แก้จำนวน / ลบ ตรงรายการ
6. "พอแล้ว จ่ายเงิน" → เปิดหน้าสรุป บอกให้แตะยืนยัน ไม่ยืนยันเอง
