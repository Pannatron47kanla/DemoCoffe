# UC-02 ยินยอมและเริ่มสั่งด้วยเสียง (Start voice session)

- **Context:** voice (ถามสถานะตะกร้าจาก ordering ผ่าน port)
- **เฟส:** 1 MVP — ตู้เดี่ยว ใช้กับพนักงานหรือผู้ทดสอบที่ยินยอมเท่านั้น
- **ข้อยกเว้นจากข้อเสนอ (ตกลง 2026-10-19):** เดโมใช้ Gemini API คีย์ฟรีจาก Google AI Studio แทน Vertex AI ห้ามใช้กับลูกค้าจริง ก่อนใช้กับลูกค้าจริงต้องเปลี่ยนเป็น Vertex AI `asia-southeast1` และผ่านผู้เชี่ยวชาญ PDPA
- **สถานะ:** ยืนยันกฎแล้ว (2026-10-19) พร้อมทำขั้นที่ 2
- **อ้างอิง:** ข้อเสนอสถาปัตยกรรม หัวข้อ "สั่งและตอบกลับด้วยเสียง"

## ผู้ใช้งาน
- ลูกค้าหน้าตู้ที่มีตะกร้าเปิดอยู่ (จาก UC-01)

## เงื่อนไขก่อนเริ่ม
- มีตะกร้าที่ยังเปิดและไม่หมดอายุ
- ข้อความยินยอมเวอร์ชันปัจจุบันอยู่ใน `data/voice-consent.json` (`version` และข้อความ) แก้ได้โดยไม่ต้อง deploy
- ระบบเปิดใช้เสียงอยู่ (ตั้งค่าที่ `api`) และมี Gemini API key ของ AI Studio ที่ `api` (ไม่อยู่ในตู้)

## ขั้นตอนหลัก
1. ลูกค้ากดปุ่มสั่งด้วยเสียงครั้งแรกในตะกร้านี้ → ตู้ขอข้อความยินยอมเวอร์ชันปัจจุบันแล้วแสดง
2. ลูกค้ากด "ยินยอมและเริ่มพูด" → ตู้ส่ง `cartId` และเวอร์ชันข้อความที่แสดง
3. ระบบบันทึกหลักฐานความยินยอม (เวลา ตู้ เวอร์ชันข้อความ ตะกร้า) และขอโทเคนชั่วคราว (ephemeral token) จาก Gemini API ให้ตู้ใช้เปิดเซสชัน Gemini Live ตรง
4. ตู้เปิดเซสชันเสียง (การสั่งผ่านเสียงอยู่ใน UC-03)
5. ถ้ากดปุ่มเสียงอีกในตะกร้าเดิม (เช่นหลังกดหยุด) ระบบออกข้อมูลเชื่อมต่อใหม่โดยไม่ถามยินยอมซ้ำ

ทางเลือก: ลูกค้ากด "สั่งด้วยการแตะแทน" → ตู้กลับไปหน้าเมนู ไม่เรียก API ไม่มีบันทึก

## กฎทางธุรกิจ
| # | กฎ |
|---|---|
| R1 | ต้องยินยอมก่อนจึงออกข้อมูลเชื่อมต่อเสียงได้ ความยินยอมนี้แยกจากความยินยอมเรื่องใบหน้าและสมาชิก |
| R2 | ความยินยอมผูกกับเวอร์ชันข้อความ ถ้าตู้ส่งเวอร์ชันที่ไม่ใช่ปัจจุบัน ให้ปฏิเสธและให้ตู้แสดงข้อความใหม่ |
| R3 | หลักฐานความยินยอมเก็บเฉพาะ เวลา ตู้ เวอร์ชันข้อความ และตะกร้า ไม่ผูกกับตัวบุคคล ไม่เก็บไฟล์เสียง |
| R4 | หนึ่งตะกร้ามีเซสชันเสียงเดียว กดเสียงซ้ำในตะกร้าเดิมไม่ถามยินยอมซ้ำและไม่สร้างบันทึกใหม่ |
| R5 | เริ่มเสียงได้เฉพาะตะกร้าที่เปิดและไม่หมดอายุ (กฎเดียวกับ UC-01 R7, R8) |
| R6 | โทเคนใช้เปิดการเชื่อมต่อได้ครั้งเดียว ต้องเริ่มภายใน 1 นาที เซสชันเสียงยาวได้ไม่เกิน 15 นาที (เสียงอย่างเดียว ไม่ส่งภาพ) การเชื่อมต่อแต่ละครั้งอยู่ได้ราว 10 นาที เมื่อหลุดหรือครบเวลา ตู้ขอโทเคนใหม่ตาม R4 แล้วต่อเซสชันเดิม (session resumption) |
| R7 | ผู้ให้บริการเสียงเลือกด้วยการตั้งค่า `VOICE_PROVIDER`: เดโมใช้ `ai-studio` (Gemini API คีย์ฟรี) ส่วน `vertex` (Vertex AI `asia-southeast1`) ไว้ใช้กับลูกค้าจริง โทเคนผูกกับรุ่นที่ตั้งไว้ (`VOICE_MODEL` ค่าเริ่มต้น `gemini-3.8-live` ซึ่งเป็นรุ่นหลักของ Live API และอยู่ใน free tier) API key ถาวรอยู่ที่ `api` เท่านั้น ไม่อยู่ในตู้ ไม่ส่งภาพ ใบหน้า ชื่อ หรือเบอร์โทร |
| R8 | ถ้าปิดใช้เสียงไว้ หรือขอข้อมูลเชื่อมต่อจาก Google ไม่สำเร็จ (รวมถึงชน rate limit ซึ่ง Google ไม่ประกาศตัวเลขและไม่รับประกัน) ให้ตอบว่าใช้เสียงไม่ได้ ตู้กลับไปสั่งด้วยการแตะ การสั่งต้องไม่สะดุด |
| R9 | `ai-studio` ใช้ได้เฉพาะ `APP_ENV` ที่ไม่ใช่ `production` ถ้าตั้งผิด `api` ต้องไม่เริ่มทำงาน (กันเผลอใช้คีย์ฟรีกับลูกค้าจริง) |
| R10 | ข้อความยินยอมของเดโมต้องบอกว่าเสียงส่งไป Google อาจถูกใช้ปรับปรุงบริการและให้คนตรวจอ่านได้ และไม่รับประกันว่าประมวลผลในสิงคโปร์ |

## Acceptance criteria
| AC | Given | When | Then |
|---|---|---|---|
| AC1 | ข้อความยินยอมปัจจุบันเวอร์ชัน `voice-demo-v1` | ตู้ขอข้อความยินยอม | ได้ `version` และข้อความ ซึ่งมีเนื้อหาตาม R10 |
| AC2 | ตะกร้าเปิดอยู่ ยังไม่มีเซสชันเสียง เวลา 09:30 | ยินยอมด้วย `voice-demo-v1` | 201 สร้างเซสชันเสียง บันทึก เวลา 09:30 ตู้ `kiosk-1` เวอร์ชัน `voice-demo-v1` ตะกร้า และคืนโทเคนชั่วคราว รุ่นที่ใช้ และเวลาที่ต้องเริ่มก่อน |
| AC3 | AC2 สำเร็จแล้ว | ดูบันทึกในฐานข้อมูล | มีเฉพาะ เวลา ตู้ เวอร์ชัน ตะกร้า ไม่มีข้อมูลบุคคลหรือเสียง |
| AC4 | ตะกร้านี้มีเซสชันเสียงแล้ว | กดเสียงอีกครั้ง | 200 เซสชันเดิม ข้อมูลเชื่อมต่อใหม่ ไม่มีบันทึกความยินยอมเพิ่ม |
| AC5 | — | ไม่ส่ง `cartId` หรือ `consentTextVersion` | 400 `VALIDATION_ERROR` |
| AC6 | — | ใช้ `cartId` ที่ไม่มี | 404 `CART_NOT_FOUND` |
| AC7 | ตะกร้าไม่ได้แก้ไขครบ 15 นาที | ยินยอม | 409 `CART_EXPIRED` ไม่มีบันทึก |
| AC8 | ตะกร้ายืนยันออเดอร์แล้ว | ยินยอม | 409 `CART_ALREADY_CHECKED_OUT` ไม่มีบันทึก |
| AC9 | ข้อความปัจจุบันเป็น `voice-demo-v2` | ยินยอมด้วย `voice-demo-v1` | 409 `CONSENT_TEXT_OUTDATED` พร้อมเวอร์ชันปัจจุบัน ไม่มีบันทึก |
| AC10 | ปิดใช้เสียงไว้ในการตั้งค่า | ขอข้อความยินยอม หรือยินยอม | 503 `VOICE_UNAVAILABLE` ไม่มีบันทึก |
| AC11 | ขอข้อมูลเชื่อมต่อจาก Google ไม่สำเร็จ ชน rate limit (429) หรือเกิน 3 วินาที | ยินยอม | 503 `VOICE_UNAVAILABLE` บันทึกความยินยอมยังอยู่ กดอีกครั้งแล้วไม่ถามยินยอมซ้ำ |
| AC12 | `VOICE_PROVIDER=ai-studio`, `VOICE_MODEL=gemini-3.8-live` | ระบบขอโทเคนจาก Gemini API | คำขอล็อกรุ่น `gemini-3.8-live` ตอบเป็นเสียง ใช้ได้ 1 ครั้ง เริ่มภายใน 1 นาที เปิด session resumption และไม่มีข้อมูลบุคคล |
| AC13 | ตะกร้าเดียว | กดยินยอมสองครั้งพร้อมกัน | ได้เซสชันเดียว บันทึกเดียว |
| AC14 | `APP_ENV=production` และ `VOICE_PROVIDER=ai-studio` | เริ่ม `api` | ไม่เริ่มทำงาน แจ้งว่าห้ามใช้ AI Studio กับ production |
| AC15 | `VOICE_PROVIDER=ai-studio` แต่ไม่มี API key | เริ่ม `api` | เริ่มได้ แต่เสียงปิด ขอข้อความยินยอมหรือยินยอมได้ 503 `VOICE_UNAVAILABLE` (การสั่งด้วยการแตะใช้ได้ปกติ) |

## นอกขอบเขต
- การสั่งผ่าน function call ของ Gemini (UC-03)
- หน้าจอตู้ (ปุ่มยินยอมกับปุ่มแตะแทนขนาดเท่ากัน ปุ่มหยุดเสียง การต่อเซสชันใหม่) — อยู่ใน UC หน้าจอตู้แยก ทำหลัง UC-02
- การยกเลิกความยินยอม (เสียงไม่ถูกเก็บ หลักฐานไม่ผูกกับบุคคล)

## ข้อมูลจาก Google (ตรวจ 2026-10-19)
- free tier: `gemini-3.8-live` (รุ่นหลักของ Live API) ใช้ฟรีได้ ส่วน `gemini-2.5-flash-native-audio-preview-12-2025` ยังไม่ยืนยันว่าอยู่ใน free tier จึงไม่ใช้
- free tier: Google อาจนำ input/output ไปปรับปรุงผลิตภัณฑ์ (ครอบคลุมใน R10)
- rate limit: Google ไม่ประกาศตัวเลขและไม่รับประกัน ดูได้ใน AI Studio รุ่น preview ได้เพดานต่ำกว่า (รองรับด้วย R8/AC11)
- ขีดจำกัดเซสชัน: เสียงอย่างเดียว 15 นาที การเชื่อมต่อแต่ละครั้งราว 10 นาทีต้องใช้ session resumption (R6)
