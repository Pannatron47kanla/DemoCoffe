# UC-01 สั่งเครื่องดื่มที่ตู้ (Place kiosk order)

- **Context:** ordering (ใช้ menu ผ่าน `MenuLookup`)
- **เฟส:** 1 MVP — ตู้เดี่ยว 1 สาขา เมนูจาก `menu.json` ยังไม่รับเงินจริง
- **สถานะ:** พัฒนาแล้ว เทสต์ครบทุก AC (2026-10-19)

## ผู้ใช้งาน
- ลูกค้าหน้าตู้ (แตะจอ)
- ผู้ช่วยเสียง (Gemini Live) ผ่าน UI ตู้ ใช้ API ตะกร้าชุดเดียวกัน — ขั้นตอนและกฎเหมือนการแตะจอทุกข้อ

## เงื่อนไขก่อนเริ่ม
- ตู้เรียก `api` บนเครื่องเดียวกันได้ (เฟส 1 ไม่มีคีย์ตู้ `api` รับเฉพาะ `127.0.0.1`)
- มีเมนูอย่างน้อยหนึ่งรายการที่พร้อมขาย

## ขั้นตอนหลัก
1. ลูกค้าเริ่มสั่ง → ระบบสร้างตะกร้าว่าง
2. ลูกค้าเลือกเมนู ตัวเลือก และจำนวน → ระบบตรวจกับเมนูจริง คิดราคา แล้วเพิ่มลงตะกร้า
3. ลูกค้าแก้จำนวนหรือลบรายการได้ ระบบแสดงตะกร้าและยอดรวมล่าสุดทุกครั้ง
4. ลูกค้ากดยืนยัน → ระบบตรวจราคาและสถานะเมนูอีกครั้ง สร้างออเดอร์ ตรึงราคา และออกหมายเลขคิว
5. ตู้แสดงหมายเลขคิวและรายการที่สั่ง

## กฎทางธุรกิจ
| # | กฎ |
|---|---|
| R1 | เมนูต้องมีอยู่และพร้อมขาย ทั้งตอนเพิ่มลงตะกร้าและตอนยืนยัน |
| R2 | กลุ่มตัวเลือกที่บังคับ (เช่น ขนาด) ต้องเลือก 1 ค่าพอดี กลุ่มไม่บังคับเลือกได้ 0–1 ค่า และตัวเลือกต้องอยู่ในเมนูนั้น |
| R3 | ราคาต่อแก้ว = ราคาตั้งต้น + ราคาเพิ่มของตัวเลือก เก็บเป็นสตางค์ ระบบคิดเอง ไม่รับราคาจากตู้ |
| R4 | จำนวนต่อรายการ 1–10 แก้ว |
| R5 | จำนวนรวมทั้งตะกร้าไม่เกิน 20 แก้ว |
| R6 | เพิ่มเมนูและตัวเลือกชุดเดียวกันซ้ำ → รวมจำนวนเข้ารายการเดิม (ยังอยู่ใต้ R4, R5) |
| R7 | ตะกร้าหมดอายุเมื่อไม่มีการแก้ไข 15 นาที แก้ไขหรือยืนยันตะกร้าที่หมดอายุไม่ได้ |
| R8 | ยืนยันตะกร้าว่างไม่ได้ ตะกร้าหนึ่งใบได้ออเดอร์เดียว |
| R9 | ถ้าราคาเมนูเปลี่ยนระหว่างอยู่ในตะกร้า ตอนยืนยันให้ปฏิเสธ คิดราคาใหม่ในตะกร้า และให้ลูกค้าดูยอดใหม่ก่อนยืนยันอีกครั้ง |
| R10 | หมายเลขคิวเรียงต่อวันทำการ (Asia/Bangkok) เริ่มที่ 1 ไม่ซ้ำภายในวัน แสดงเป็นเลขล้วน |
| R11 | การยืนยันต้องแนบ idempotency key: key เดิมกับตะกร้าเดิมคืนออเดอร์และคิวเดิม ไม่ออกคิวใหม่ key หนึ่งใช้กับตะกร้าเดียว |
| R12 | ออเดอร์ที่ยืนยันแล้วมีสถานะ `PLACED` (เฟส 1 ยังไม่มีขั้นจ่ายเงิน) และเก็บชื่อเมนู ตัวเลือก ราคา ณ ตอนยืนยัน |

## AC → API → DB
| AC | API ตอบ | DB ช่วยกันไว้ |
|---|---|---|
| AC1 | `POST /carts` 201 `Cart` | `carts.status` CHECK, NOT NULL |
| AC2–AC5 | `POST/PATCH/DELETE /carts/{id}/lines…` 200 `Cart` | `cart_lines.unit_price_satang >= 0` |
| AC3 (R6) | 200 `Cart` | UNIQUE (`cart_id`, `menu_item_id`, `option_choice_ids`) |
| AC6 | 400 `VALIDATION_ERROR` | NOT NULL ทุกคอลัมน์บังคับ |
| AC7, AC8, AC9, AC10 | 404 / 409 | — (เมนูอยู่ใน `menu.json`, ตรวจใน domain) |
| AC11 | 409 `QUANTITY_OUT_OF_RANGE` | CHECK `quantity BETWEEN 1 AND 10` (`cart_lines`, `order_lines`) |
| AC12 | 409 `CART_LIMIT_REACHED` | — (ผลรวมข้ามแถว ตรวจใน domain) |
| AC13 | 404 `CART_NOT_FOUND` / `CART_LINE_NOT_FOUND` | FK `cart_lines.cart_id` |
| AC14 | 409 `CART_EXPIRED` | `carts.last_activity_at` NOT NULL |
| AC15 | `POST /carts/{id}/checkout` 201 `Order` | `orders.status` CHECK, `queue_number > 0` |
| AC16, AC17 | 201 `Order.queueNumber` | `queue_counters` PK `business_day` |
| AC18 | 200 `Order` เดิม | UNIQUE `orders.idempotency_key` |
| AC19 | 409 `CART_ALREADY_CHECKED_OUT` | UNIQUE `orders.cart_id` |
| AC20 | 409 `CART_EMPTY` | — (domain) |
| AC21 | 409 `MENU_ITEM_UNAVAILABLE` + `details.lineIds` | — (domain) |

| AC24 | `Order` ใช้ snapshot ยอดรวมคิดจาก `order_lines` | `order_lines.menu_item_name`, `options`, `unit_price_satang` NOT NULL |
